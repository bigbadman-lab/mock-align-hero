# Native rewards rules
- Rewards tx assembly lives only in services/rewards-worker/src/assembly.ts (unsigned, allowlisted programs, deployer-only signer); holder history via src/lib/rewards/holder-index.ts — signing/sending stays out of the repo until approved.
- Native rewards use one deployer wallet (feeModel SINGLE_DEPLOYER, native-single.ts): ledger-enforced 30/30/40, no onchain sharing or extra treasuries — keeps MVP to one signer.
- Native rewards (src/lib/rewards): pure integer economics/epochs/snapshot/ledger with injectable store; tables mcpx_rw_* are service-role only, append-only, carry-chained and conservation-checked in SQL; no execution paths — fee proof = Pump self-CPI events with event-authority check (pump-events.ts); the window processor (processor.ts) emits DRY_RUN plans only; durable state via store.pg.ts + SQL mcpx_rw_commit_window (DB re-derives totals, single lease, +1-window watermark); runs only in services/rewards-worker (Background Worker), never the MCP tool worker or a site request; see docs/REWARDS_05A.md.
- Holder history source = Helius gTFA(mint)+per-account history, verified each pass by getMultipleAccounts at one finalized slot (services/rewards-worker/src/helius-history.ts, holder-sync.ts); websocket streams are hints only, never completeness proof.
- Window snapshots (05-I): cutoff = last produced finalized slot with blockTime < window end (cutoff.ts); the index never advances past an unselected window end; supply at cutoff is proven from mint-at-V minus own-program MintTo/Burn deltas (supply-proof.ts); freeze + checkpoint CAS in one tx (cutoff-snapshot.pg.ts); frozen rows immutable, late data → holds; schema in docs/pending-migrations/0010 until approved; see docs/REWARDS_05I.md.
- Recovery (05-I.1): operator CLI scripts/recover-window.ts builds immutable non-payable candidates (recovery.ts); holds close only via SQL mcpx_rw_hix_resolve_window on exact fingerprint match; mismatches need a policy decision; cutoff search seeded by prior frozen cutoff as a hint only (selectCutoffBaseline kept for equivalence).
- Worker⇄site bridge (src/lib/rewards/remote.ts, /api/public/rewards/{exec,state}): Render worker has no DB login; sealed HMAC batches run in one transaction via service-role-only mcpx_rw_remote_exec; multi-statement writes go through runTx (store.pg.ts) so direct and remote stores share the same steps; mint/launch config lives in mcpx_rw_config — setting the mint is the only go-live step.
- Deployer signer (services/rewards-worker/src/signer.ts, worker-only): one base58 64-byte key in Render env MCPX_DEPLOYER_PRIVATE_KEY, must derive MCPX_DEPLOYER_PUBLIC_KEY or signing is refused; signs SOL/token payouts that exactly match plan rows, plus fee collection and buybacks only through venue-check.ts (allowlisted Pump/PumpSwap instruction shapes, deployer-only accounts, max spend ≤ the window's reserved buyback budget), within the fee-backed epoch budget reserved atomically in SQL (mcpx_rw_budget_remaining; env caps are optional emergency ceilings only), after a durable idempotent intent; executor.ts persists signed bytes before any send and only resends identical bytes (sender injected, null = broadcast disabled); key presence never makes execution ready (executionReadiness) — keeps money movement behind real proofs.
- Cycle wiring (01D, services/rewards-worker/src/pipeline.ts): entitlements only from the window's frozen snapshot; income only from finalized collect events with deployer provenance (vault balance is just a trigger); payouts persist exact plan_rows+message bytes (0020, DB-enforced) and land only on proof against that plan; fills recorded from finalized token deltas, never quotes.
- Child-fee keeper (services/rewards-worker/src/child-fees*.ts, child-wire.ts, child-chain.ts, child-store.pg.ts): runs each Rewards Worker pass via the sealed bridge, isolated from mcpx_rw_* (state only in mcpx_cf_*, registry read-only; remote.ts guard allows exactly that); only permissionless Pump sweep/distribute to on-chain-locked shares that equal registry creator 60% / env ops 25% / env platform 15%, re-checked before build and before any resend; plan-only (signingEnabled=false, send=null) until approved — keeps child fees separate from native rewards and unable to move funds early.
- SOL rehearsal (Worker #3, launch-verify.ts): the claim matching the SUBMITTED 0027 permission is checked only by verifyRehearsalLaunch (native SOL quote, locked 60/25/15) and registered+consumed in one SQL call mcpx_cf_register_rehearsal; it runs before the $MCP-mint gate, every claim is held if the permission is unreadable, and the token is never onboarded to the child-fee keeper (pendingRegistry filters on the $MCP quote) — so the rehearsal never mixes into $MCP accounting.
- Launch wake: between launch passes Worker #3 polls the sealed /api/public/rewards/launch-pending read every ~5 s (services/rewards-worker/src/launch-wake.ts) so new launches register in seconds without inbound HTTP to the worker; the timed poll stays as a fallback.
