# Native rewards rules
- Rewards tx assembly lives only in services/rewards-worker/src/assembly.ts (unsigned, allowlisted programs, deployer-only signer); holder history via src/lib/rewards/holder-index.ts — signing/sending stays out of the repo until approved.
- Native rewards use one deployer wallet (feeModel SINGLE_DEPLOYER, native-single.ts): ledger-enforced 30/30/40, no onchain sharing or extra treasuries — keeps MVP to one signer.
- Native rewards (src/lib/rewards): pure integer economics/epochs/snapshot/ledger with injectable store; tables mcpx_rw_* are service-role only, append-only, carry-chained and conservation-checked in SQL; no execution paths — fee proof = Pump self-CPI events with event-authority check (pump-events.ts); the window processor (processor.ts) emits DRY_RUN plans only; durable state via store.pg.ts + SQL mcpx_rw_commit_window (DB re-derives totals, single lease, +1-window watermark); runs only in services/rewards-worker (Background Worker), never the MCP tool worker or a site request; see docs/REWARDS_05A.md.
- Holder history source = Helius gTFA(mint)+per-account history, verified each pass by getMultipleAccounts at one finalized slot (services/rewards-worker/src/helius-history.ts, holder-sync.ts); websocket streams are hints only, never completeness proof.
- Window snapshots (05-I): cutoff = last produced finalized slot with blockTime < window end (cutoff.ts); the index never advances past an unselected window end; supply at cutoff is proven from mint-at-V minus own-program MintTo/Burn deltas (supply-proof.ts); freeze + checkpoint CAS in one tx (cutoff-snapshot.pg.ts); frozen rows immutable, late data → holds; schema in docs/pending-migrations/0010 until approved; see docs/REWARDS_05I.md.
- Recovery (05-I.1): operator CLI scripts/recover-window.ts builds immutable non-payable candidates (recovery.ts); holds close only via SQL mcpx_rw_hix_resolve_window on exact fingerprint match; mismatches need a policy decision; cutoff search seeded by prior frozen cutoff as a hint only (selectCutoffBaseline kept for equivalence).
- Worker⇄site bridge (src/lib/rewards/remote.ts, /api/public/rewards/{exec,state}): Render worker has no DB login; sealed HMAC batches run in one transaction via service-role-only mcpx_rw_remote_exec; multi-statement writes go through runTx (store.pg.ts) so direct and remote stores share the same steps; mint/launch config lives in mcpx_rw_config — setting the mint is the only go-live step.
- Deployer signer (services/rewards-worker/src/signer.ts, worker-only): one base58 64-byte key in Render env MCPX_DEPLOYER_PRIVATE_KEY, must derive MCPX_DEPLOYER_PUBLIC_KEY or signing is refused; signs only SOL/token payouts that exactly match plan rows, within env spend caps, after a durable idempotent intent; no broadcast code; key presence never makes execution ready (executionReadiness) — keeps money movement behind real proofs.
