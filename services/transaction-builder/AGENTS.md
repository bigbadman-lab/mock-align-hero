# Transaction builder rules

- Transaction builder: separate Render service in services/transaction-builder (own pinned deps incl. @pump-fun/pump-sdk loaded via CJS, own HMAC secret, exactly one instance) that only builds unsigned, MAC-bound candidates from official SDK instructions — creation (create_v2+fee config+creator-vault quote ATA+60/25/15) atomic, optional buy a separate later transaction gated on on-chain fee verification — simulates read-only and never signs/submits; recipients, 60/25/15 split, quote mint, RPC, programs and ALT are server env only; website reads only its /ready via src/lib/tx-builder/status.server.ts — keeps launch code and keys out of the site and the MCP worker.
- Child creator binding: site route /api/creator/launch-prepare (off unless MCPX_CHILD_LAUNCH_ENABLED=1) runs src/lib/tx-builder/launch-gate.ts — 60% creator = SIWS session wallet signed in ≤10 min ago, connected wallet must match, builder candidate re-inspected before signing; keeper verifyRecipients holds payouts unless chain shares = registered creator/env ops/env platform; builder refuses to start without MCPX_NATIVE_DEPLOYER_PUBLIC_KEY, with conflicting recipients, or with any private-key variable — so neither browser nor config error can redirect child fees.
